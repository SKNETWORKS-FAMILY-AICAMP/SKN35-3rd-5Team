# 판정 모델 개발셋 비교 및 수치 대조 회귀 테스트

평가일: 2026-10-13 (한국 시간). 모델: `gpt-4o-mini`, temperature=0.
대상: 팀 작성 개발셋 45문항(가능 12, 조건부 7, 불가 26).
최종 평가용 holdout 21문항은 실행하지 않았다.

## 평가 범위와 계획

동일한 광고 문구·제품 정보로 R0 규칙, R1 GPT zero-shot, R2 GPT few-shot을 각각 1회 평가했다.
GPT에는 제품 이름·분류·기능성 유형·보유 시험만 전달하고 정답·메모는 전달하지 않았다.
프롬프트 버전은 `judge-zero-shot-v2`, `judge-few-shot-v2`이며 few-shot은 별도 예시 8개다.
이번 결과는 검색·문구 제안·역검증을 제외한 독립 사전 판정의 결과다.
실패한 API 호출은 분모에서 제외하지 않고 실패·오답으로 계산한다.

실행 명령:

```powershell
uv run python -m eval.run_eval --backend rule gpt gpt-few --split dev
```

‘위반 탐지율 100%’는 불가와 조건부를 정확히 구분했다는 뜻이 아니다.
few-shot은 불가를 조건부로 낮추는 오류를 줄였지만 정상 문구의 과잉 경고를 늘렸다.
그 결과 전체 정확도는 올라갔지만 Macro-F1은 내려갔다. few-shot의 일괄 도입 근거로 삼지 않는다.

## 오류 분석과 의사결정

- R1 `G_DEV_002`: 보유 시험과 다른 수치를 인식했으나 불가(2)가 아닌 조건부(1)로 분류했다.
- R1·R2 `G_DEV_028`: 팀 정답상 불가인 주장을 두 방식 모두 조건부로 낮췄다.
- 기능성 심사 범위 내 표현에도 별도 실증을 요구하거나, 일반 세정 설명을 기능성 주장으로 해석해 과잉 경고했다.
- 대표 위반 유형도 혼동했다. 수준 정확도와 유형 정확도를 별도로 관리한다.

현 단계에서는 명확한 규칙·수치 대조를 하한으로 유지하고, GPT 단독으로 기존 규칙 판정을 낮추지 않는다.
GPT 프롬프트와 정답 기준의 일관성, 특히 기능성 심사와 일반 실증의 구분을 다음 개발 과제로 둔다.
이번 실행 뒤 프롬프트를 수정하거나 동일 개발셋에 맞춰 재평가하지 않았다.

## 수정 및 회귀 검증

기존 코드는 모든 시험의 숫자를 합쳐 확인했다. 보습 시험 ‘4주·35%’와 탄력 시험 ‘2주·70%’가
있을 때 ‘2주 보습력 70% 개선’을 가능(0)으로 통과시켰다.

수정 후에는 한 문장의 수치·기간이 같은 효능의 단일 시험 결과에 함께 존재해야 한다.
같은 효능의 서로 다른 시험끼리 숫자를 조합하는 경우도 차단한다.
서로 다른 문장은 각각의 시험을 참조할 수 있고, 시험기관 이름에 포함된 숫자는 결과로 인정하지 않는다.
또한 실제 워크플로의 하한 게이트가 금지어뿐 아니라 수치 충돌·실증 부족까지 반영하도록 연결했다.

추가 회귀 사례: 다른 효능 수치 차용, 같은 효능 시험 간 수치 조합, 정상 수치 일치,
별도 문장별 독립 시험, 기관명 숫자 오용, GPT가 낮게 판정해도 수치 충돌 유지, 근거 없음의 조건부 처리.

최종 검증: `python -m pytest -q` 전체 98개 통과, 변경 코드의 Ruff 검사 통과.
그래프 테스트의 가짜 규칙 엔진도 새 `evaluate` 호출 계약에 맞췄다.

로컬 검색 테스트를 위해 저장소 청크 59개로 BM25 파일만 생성했다. 공유 Qdrant에는 접근하지 않았다.
이 파일은 테스트 실행 준비용이며 화면에 기재된 팀의 175개 조문 인덱스와 동일하다고 주장하지 않는다.
