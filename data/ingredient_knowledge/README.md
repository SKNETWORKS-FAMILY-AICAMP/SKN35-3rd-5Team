## 적용 기준

- 제품에 직접 입력된 주요 성분·전성분에 해당하는 카드만 전달한다. 제품명만으로 성분 함유를 추정하지 않는다.
- 성분명 중심, 제품 특징 중심, 사용 상황 중심으로 표현 방식을 달리하되, 사용감·타깃 적합성·자극 없음도 입증된 사실처럼 단정하지 않는다.
- 미백·주름 등 기능성 주장은 제품의 기능성 정보로 제한하고, 수치·시험 결과는 해당 제품의 보유 실증으로만 사용한다.
- 논문의 농도·기간·대상·수치를 자사 제품 문구로 복사하지 않는다. 각 카드에 연구 조건과 출처를 보존한다.
- PDRN 관련 원료 표기만으로 PN/PDRN 동일성·분자량·순도를 확정하지 않는다. 병풀추출물과 관련 단일 분자를 구분한다. 스쿠알란과 스쿠알렌, 레티놀과 레티날도 구분한다.
- 연구에서 평가한 역할은 광고 허용 목록이 아니다. 기존 규칙·RAG 검토와 제품 시험 확인이 필요하다.

## 빠른 확인 예시

광고문 생성에서 히알루론산·판테놀을 주요 성분으로 등록한 토너를 선택한다. 「이 제품 성분으로 잡은 표현 방향」에서 수분·보습 역할과 제한을 확인하고 생성한다. 성분명 나열만 요청하기보다 「성분 강조형과 데일리 보습 루틴형으로 다르게 작성」처럼 요청한다.

## 구현·확인

- `generation/ingredients.py`가 직접 입력된 성분만 매칭하고 역할 정보를 규정·시장 참고와 구분해 생성기에 전달한다. 연구 자료를 보유 실증으로 등록하지 않는다.
- 응답의 `ingredient_profiles`에 연결 자료를, 후보의 `ingredient_reference_ids`·`ingredient_application`에 반영 내역을 남긴다. 매출 화면에서도 같은 후보의 설명을 표시한다.
- 성분 지식이 바뀌면 이전 생성 결과를 그대로 사용하지 않고 재생성을 안내한다.
- 전체 단위 테스트180개 통과. 등록 성분 한정, 비슷한 원료 구분, 연구 수치·기능성 주장 자동 허용 방지, 화면 표시를 확인했다.
- 실제 `/generate` 호출HTTP200, 히알루론산·판테놀 프로필2개와 문구3개 반환. 성분 중심 후보는I1, 데일리 보습 루틴 후보는I2를 참고했다고 응답했다. 응답은 `api_smoke.json`에 보존했다.
- 자동 검증 통과는 최종 광고 승인이나 제품 효능 입증을 의미하지 않는다. 실제 광고 사용 전 제품별 자료·표현 조건을 확인한다.
