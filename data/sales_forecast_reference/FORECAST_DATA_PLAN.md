# 예상 매출·판매량 연결 데이터 작업 지시서 v1.0

작성일 2026-10-14 · 담당 준호(데이터·평가) · 작업 위치 `data/sales_forecast_reference/`

## 0. 목표

서비스 흐름을 **광고 문구 판정 → 수정·추천 → 추천 문구 사용 시 예상 매출·판매량**까지 보여주는 것으로 확장한다.
이 문서는 마지막 단계(예상 매출·판매량)에 필요한 데이터를 모으고 계산하는 작업 범위를 정한다.

공개 데이터로는 "이 문구를 쓰면 매출이 X원 오른다"를 **학습해서 예측할 수 없다**
(같은 제품에서 문구만 바꾼 실제 판매 로그가 없다). 그래서 예상 매출을 두 갈래로 나눠 보여준다.

| 구분 | 질문 | 근거의 성격 |
|---|---|---|
| **① 하방: 위험 매출** | 위험 문구를 그대로 쓰다 적발되면 얼마를 잃는가 | 법령 처분 기준 기반 계산 (가장 강한 근거) |
| **② 상방: 기대 매출** | 추천 문구로 판매할 때 기대 매출·판매량은 어느 범위인가 | 공개 벤치마크 범위를 넣은 시나리오 |

## 1. 계산식

```
월 기준 판매량(units_base)   = 리뷰 기반 추정 범위 또는 사용자 입력
월 기준 매출(revenue_base)   = units_base × 객단가(판매가, 구성 반영)

② 기대 매출(추천 문구)       = revenue_base × (1 + 문구 효과 범위)
   - 문구 효과 범위는 하나의 숫자가 아니라 분포(예: p25 ~ p75)로 적용
   - 추천 문구 A/B/C에 서로 다른 단정 숫자를 붙이지 않는다. 같은 범위를 공통 적용한다.

① 위험 매출(원문 유지 시)     = revenue_base × 정지 개월 수 (위반 유형·차수별)
   - 판정 결과 level 2 의 violation_type 과 별표5 목(가·나·카 / 다~차)으로 정지 기간을 고른다
   - 적발 확률은 공개 자료로 추정할 수 없으므로 "적발 시 최대 노출 금액"으로 표시한다
```

## 2. 데이터셋 (우선순위 순)

### D1. 행정처분 기준표 — 지금 있는 자료로 바로 작성

- 출처: `data/01_raw/law/화장품법_시행규칙.xml` 행정처분 기준 표 (법 제13조 위반, 법 제24조 제1항 제10호)
- 확인된 내용(원문 대조 후 그대로 옮길 것):
  - 별표5 제2호 **가·나·카목** 위반: 1차 해당 품목 판매업무정지 3개월(표시 위반) 또는 광고업무정지 3개월(광고 위반), 2차 6개월, 3차 9개월
  - 별표5 제2호 **다목~차목** 위반: 1차 2개월, 2차 4개월, 3차 6개월, 4차 12개월 (표시·광고 구분 동일)
- 산출물: `penalty_schedule.json`
  ```json
  {"rule_items": ["2가","2나","2카"], "violation_types": ["의약품오인","기능성오인"],
   "sanction": {"표시": "판매업무정지", "광고": "광고업무정지"},
   "months_by_offense": [3, 6, 9], "source_article": "...", "source_file": "...", "verified_against_raw": true}
  ```
- 우리 violation_type 과 별표5 목의 연결표를 함께 둔다 (rule 엔진의 `law_id` 가 `LAW_시행규칙_별표5-2가` 형식이므로 그대로 매핑 가능).
- 주의: 처분 기준의 감경·가중 조항(일반 기준)도 확인해서 한계로 적는다.

### D2. 리뷰 수 → 판매량 보정 — 신규 수집

- 아이디어: **누적 판매량이 공개된 제품**의 같은 시점 리뷰 수를 모아 "리뷰 1개당 판매량" 비율을 만든다.
  이 비율을 올리브영 상위 제품의 리뷰 수(이미 보유: 아누아 14,035 등)에 적용해 판매량을 **범위로** 추정한다.
- 보정용 후보: 아토베리어365 크림(누적 900만개, 2025-12-03 보도 — 이미 `public_outcomes.json`에 있음) 등
  공식 보도자료에 누적 판매량이 나온 제품 2~5개.
- 수집 필드: product_label, 누적 판매량, 판매량 집계 범위(채널·기간·용량 포함 여부), 보도일,
  같은 제품군의 리뷰 수(플랫폼별, 수집일), 출처 URL
- 산출물: `review_to_units_calibration.jsonl`, 비율은 최소·최대·중앙값으로만 기록
- 주의: 누적 판매량은 전 채널·장기간이고 리뷰는 플랫폼별이라 범위가 크다.
  보정 제품이 적으면 결과를 "규모 감 잡기용 범위"로만 표시한다. 단일 값으로 쓰지 않는다.

### D3. 가격·객단가 — 거의 완료

- 기존 `top_product_copies/wrinkle_serum_sample/products.csv` 와 `market_reference/offers.json` 의 표시가·할인·구성을 재사용
- 추가할 것: 1개 단위 가격(기획 세트는 구성 수로 나눈 값 별도 필드), 수집일
- 산출물: 기존 파일에 필드 추가 또는 `price_basis.jsonl`

### D4. 뷰티 이커머스 전환율·클릭률 벤치마크 — 신규 수집

- 공개 업계 리포트·광고 플랫폼 공식 자료에서 **뷰티/화장품 카테고리** 값을 모은다.
- 필수 필드: metric(CTR/CVR), 값 또는 범위, 분모 정의(노출/클릭/방문), 국가, 채널(검색/소셜/쇼핑몰), 연도, 출처 URL
- 산출물: `funnel_benchmarks.jsonl`
- 주의: 국가·채널·분모가 다르면 같은 열에 섞지 않는다. 국내 값이 없으면 해외 값임을 표시한다.
  ROAS 개선율을 CVR로 바꾸지 않는다.

### D5. 문구 변경 효과 크기 분포 — 이미 받은 원자료로 계산

- `copy_comparison/headline_comparisons.jsonl`(Upworthy 148쌍)의 **상대 CTR 차이 분포**를 계산한다:
  |B/A − 1| 의 p25 / 중앙값 / p75 / p90, 95% 구간이 0을 포함하지 않는 쌍의 비율
- 의미: "문구만 바꿨을 때 클릭률이 보통 이 정도 범위로 움직인다"는 **크기의 기준**
- 산출물: `copy_effect_size_distribution.json`
- 주의: 미국 뉴스 제목 클릭이다. 화장품 구매 전환이나 매출에 그대로 적용하지 않는다.
  화면에서는 "다른 분야 실험에서 관찰된 문구 효과 크기를 참고한 가정 범위"로 표시한다.
  뷰티 분야 공개 A/B 사례가 있으면 같은 형식으로 추가하고 출처를 분리한다.

### D6. 시장 규모 (맥락용) — 신규 수집, 낮은 우선순위

- 통계청 온라인쇼핑동향의 화장품 거래액(월·연)
- 산출물: `market_size_context.json`. 발표 맥락 슬라이드용이며 계산식에는 넣지 않는다.

## 3. 계산 모듈 (데이터 수집 후)

`app/services/copy_performance.py` 옆에 `revenue_scenario.py` 를 추가한다.

- 입력: 제품(가격·구성), 판정 결과(level, violation_type, law_id), units_base(D2 범위 또는 사용자 입력)
- 출력:
  ```json
  {"revenue_base": {"low": ..., "mid": ..., "high": ...},
   "expected_with_recommended_copy": {"low": ..., "high": ..., "effect_range_source": "D5"},
   "revenue_at_risk_if_unchanged": {"months": 3, "amount_mid": ..., "basis": "LAW_시행규칙_별표5-2가 1차"},
   "assumptions": [...], "display_label": "가정 기반 시나리오 · 학습된 예측 아님"}
  ```
- 모든 입력값은 출처 ID 또는 "사용자 입력"으로 표시한다. 미확인 값은 0으로 채우지 않고 null.

## 4. 이미 있는 것 (재사용, 중복 수집 금지)

- `forecast_input_template.json` : 공식 틀 (planned_clicks × purchase_probability × …)
- `product_sales_observations.jsonl` : Qoo10 행사 판매액 2건 (제품군 참고용)
- `beauty_campaign_cases.jsonl` : 뷰티 광고 사례 5건 (ROAS 등, 문구 효과로 쓰지 않음)
- `copy_comparison/market_copy_judgements.jsonl` : 시장 문구 46개의 판정 결과 (scripts/judge_market_copies.py)
- `market_reference/public_outcomes.json` : 올리브영 브랜드 실적·누적 판매량 등 15개 지표

## 5. 하지 말 것

1. 추천 문구별로 서로 다른 매출 숫자를 단정해 붙이기
2. 해외·타 업종 전환율, Upworthy 클릭률을 우리 제품의 값처럼 쓰기
3. 리뷰→판매량 비율, 문구 효과를 단일 값으로 쓰기 (항상 범위)
4. 적발 확률을 지어내기 (공개 자료로 추정 불가 → "적발 시 최대 노출 금액"으로만 표시)
5. 브랜드 매출을 제품·문구에 배분하기
6. 회사-브랜드-ODM 관계, 새 플랫폼 확장 등 범위 밖 수집

## 6. 작업 순서와 완료 기준

| 순서 | 작업 | 완료 기준 |
|---|---|---|
| 1 | D1 처분 기준표 | 원문 대조 표기, violation_type·law_id 매핑, 테스트 1개 |
| 2 | D5 효과 크기 분포 | 분포 수치 + 계산 스크립트 재실행 가능 |
| 3 | D3 가격 보강 | 1개 단위 가격 필드 |
| 4 | D2 리뷰 보정 | 보정 제품 2개 이상, 비율 범위 |
| 5 | D4 벤치마크 | 분모·국가·채널이 명시된 값 5개 이상 |
| 6 | 계산 모듈 | 위 JSON 형식 출력, 단위 테스트 |
| 7 | D6 시장 규모 | 선택 |

각 단계가 끝나면 `README.md` 표를 갱신하고 `uv run pytest` 가 통과해야 한다.
먼저 D1·D5 결과를 보여주고, 형식 확인 후 D2부터 진행한다.
