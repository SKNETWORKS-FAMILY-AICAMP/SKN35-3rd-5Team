## 1. 계획서 메인

### 1-1. 프로젝트 개요

화장품 광고 문구를 넣으면 화장품법·식약처 고시·관리지침·적발 사례에서 근거 조항을 찾아 판정하고,
회사가 보유한 실증 자료가 허용하는 범위 안에서 가장 설득력 있는 문구로 고쳐 주는 사내 AI 검수 에이전트다.

| 항⁠목 | 내용 |
| --- | --- |
| 주⁠제⁠(⁠과⁠제⁠ ⁠요⁠구⁠) | LLM을 연동한 내외부 문서 기반 질의응답 시스템 |
| 목⁠표 | 규정 문서를 조항 단위로 청크·임베딩해 Qdrant에 저장하고, LangGraph로 판정 → 근거 검색 → 문구 제안 → 검증을 잇는 RAG 에이전트 |
| 차⁠별⁠점 | ① 모든 판정에 근거 조항 번호 표시 ② 같은 문구도 제품(일반/기능성)과 보유 실증 자료에 따라 판정·제안이 달라짐 ③ GPT가 만든 제안 문구를 법령 기반 규칙으로 코드가 다시 검증 (숫자 날조·금지어 재등장·자사 조사 수치 차단) |
| 데⁠모⁠ ⁠포⁠인⁠트 | "단 4주 만에 보습력 42% 폭발적 개선 입증! 손상 피부 완벽 재생!" → 불가 판정 + 근거 + "4주 사용 후 보습력 42% 개선(인체적용시험)" 제안 / 실증 자료 체크 해제 시 제안 단계가 내려감 / 같은 '탈모 증상 완화' 문구가 일반 샴푸는 불가, 탈모 기능성 샴푸는 가능 |

```text

```

| 단⁠계 | 담당 |
| --- | --- |
| 1. 법령·고시·지침·적발 사례·성분 사전 수집 | 이⁠형⁠민 |

### 1-5. 협업 규칙

- 브랜치: 담당자 브랜치(`kgm`, `kjh`, `yjh`, `lsh`, `lhm`) → `dev` → `main`
- 작업 시작 전 `dev`를 받아와 충돌을 작게 유지 (`git pull origin dev`)
- `main`은 배포 기준이다. `main` 반영 후 `uv run python scripts/deploy_render.py`로 배포 (push만으로 자동 배포 안 됨)
- 검색 holdout(`data/golden_set/holdout.jsonl`)은 고정 회귀셋으로 반복 사용하며 블라인드 최종 성능으로 표현하지 않는다
- API 키·Qdrant 키·배포 훅 주소는 `.env`와 Render 환경변수에만 둔다
- 판정 규칙은 JSON을 직접 고치지 않고 `scripts/build_rule_assets.py`를 고친 뒤 다시 생성한다
